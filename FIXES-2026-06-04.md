## 1. Code fixes (verified real, in-scope)

### D — Privacy purge missed unpaid rows  *(best catch in the batch)*
`core/db/operations.py :: purge_old()` filtered `WHERE paid_at < :before`. Abandoned charges stay
`status='pending'` with `paid_at = NULL`, so `NULL < x` is false → their donor name/message were
retained **forever**, breaking the 90-day purge promise (PDPA). Now also sweeps
`status='pending' AND created_at < :before`.
Regression: `test_purge_old_covers_pending_pii`.

### A (F6) — TOCTOU race on `event_seq`
The push path read `seq = db.next_seq()` (a separate `SELECT MAX(event_seq)+1` under a shared
lock) and wrote it later in `mark_pushed()`. Two tips completing within the ~5 s `process_tip`
window (`routes/webhook.py:127`, `timeout=5.0` — confirmed) both read the same MAX → duplicate
`event_seq` → SSE `Last-Event-ID` replay skips/dupes a tip.

**Fix:** `mark_pushed(charge_id)` now allocates the seq **inside the UPDATE** via a subquery and
returns it with `RETURNING event_seq`:
```sql
UPDATE tips SET pushed_at=:now,
    event_seq=(SELECT COALESCE(MAX(event_seq),0)+1 FROM tips WHERE event_seq IS NOT NULL)
WHERE charge_id=:charge_id AND pushed_at IS NULL
RETURNING event_seq
```
Returns the seq on first push, `None` if already pushed (callers skip the broadcast — double-push
guard preserved). Callers in `routes/webhook.py`, `app/reconciliation.py` (3 sites) updated; the
transient non-persisted uses (`routes/dev.py`, `routes/sse.py` manual replay) keep `next_seq()`.
Regressions: `test_mark_pushed_atomic` (new contract: seq / `None`), `test_mark_pushed_allocates_distinct_seqs`.

> **Correction to my earlier advice.** I told you "A must be bundled with C (IMMEDIATE
> transactions)." **C is not needed.** Folding `MAX` into the UPDATE *statement* makes allocation
> atomic on its own: an UPDATE holds the write lock before its SET subquery evaluates, so a
> concurrent `mark_pushed` blocks on `busy_timeout` and only reads MAX after the first commits.
> The deadlock pattern IMMEDIATE guards against (read-then-write in one transaction) exists in **no**
> write path here, and an engine-wide `BEGIN IMMEDIATE` would force read-only `connect()` blocks to
> take the write lock too (kills WAL read concurrency). So I dropped C deliberately — lower risk,
> same correctness. Blast radius if the lock reasoning were ever wrong: overlay display only
> (skipped/duped tip on reconnect). Money idempotency is a **separate** key (`charge_id` PK +
> `status!='successful'`) and is untouched — no money-loss path either way.

### B — Rate-limiter unbounded dict growth
`core/ratelimit.py` kept one deque per IP and never evicted empty ones → unbounded memory under IP
churn (OOM DoS). Added threshold-triggered `_evict_stale()` (drops keys whose newest hit is outside
the window) past `max_keys=10_000`; the common path stays O(1). *Practical severity was low —
`/api/charge` sits behind the tunnel with `cf-connecting-ip` set authoritatively by Cloudflare — but
the fix is cheap.*

## 4. Deliberately NOT done (rejected from the reports — out of scope / wrong frame)

Per CLAUDE.md LOCKED scope + "do not over-engineer." All from `ultimate_security_hardening.md`,
`ipo_ready_audit.md`, parts of `secure_extensibility_extensions.md`:

- Postgres / Alembic / PgBouncer, Celery/RQ async queue, Vault/Secrets Manager, Prometheus/Sentry/
  OTel, Locust — explicit out-of-scope list; this is a single-machine self-host PoC, not pre-IPO SaaS.
- Column-level PII encryption — single self-host box; the key sits beside the data; an attacker with
  raw SQL read already owns the machine. Marginal.
- Async webhook queue — adds a money-loss failure mode (queue drop on crash) unless persisted; worse
  than the lock it "fixes" at this scale.
- ⚠️ **MockPaymentAdapter / `DEV_TEST_TRIGGER` bypass** (`secure_extensibility` §3) — a backdoor that
  forges charges + webhooks on the Secure Core payment path. Security risk, not convenience. Skipped.
- Pydantic settings *fallback-to-defaults* — conflicts with fail-closed startup self-test for
  security-relevant settings. Skipped (fine only for cosmetic fields).
- TTS / donor-pays-fee / moderation skeletons (`vibecode_scaffolding_plan.md`) — roadmap, not PoC.
- SQLite `IMMEDIATE` transactions (audit Issue C) — see §1 A: not needed; no write path has the
  read-then-write pattern it guards, and `busy_timeout=5000` covers short writes.
